# F8b — Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This phase runs **inline in
> one session** — no parallel agents, no subagents, no Workflow (user's standing rule).

**Goal:** The reports module of 01 §7.14: live monthly and yearly tabs over a combined multi-building
preview, one persisted report per building with its PDF and Excel, e-mail delivery with both files
attached through the company's SMTP settings, the archive tab, and the `report.generate` /
`report.deliver` jobs with their monthly and yearly schedules.

**Architecture:** One new **pure** package, `internal/domain/report`, turns per-building, per-month
figures into the monthly and yearly report (every §10 formula is a table test there, including the
hand-computed fixture 09 §F8 asks for). `internal/service/report` does the scoped reads
(consumption aggregates, building bills, plants, plant production, feed-in and grid-factor lookups),
feeds the pure builder, and owns generation, storage and delivery. Two renderers
(`internal/render/reportpdf`, `internal/render/reportxlsx`) take the **stored payload** as their only
input, so a file rendered today and one rendered from the archive next year are the same. Mail
gains multipart (attachments + an HTML alternative). Seven 05 §11 routes, three permissions, three
job types plus two dispatch ticks, and one screen with three tabs following R195–R199/R229/R249.

**Tech Stack:** Go 1.27 (asynq, pgx/sqlc, shopspring/decimal, swaggest OpenAPI, excelize, go-pdf/fpdf),
Postgres 17 + TimescaleDB, Redis, Next.js 15 App Router + React 19, TanStack Query via
`openapi-react-query`, Tailwind v4, Vitest + Storybook + Playwright.

## Binding rulings (R254–R275)

Numbering continues from F8a's R253.

| # | Ruling |
|---|---|
| **R254** | **Consumption is the calendar month, from the aggregates.** 02 §10.1 defines total consumption as Σ `active_import` for the month: `consumption.Analytics.Consumption` at `energy.Monthly` over the building's non-deleted analyzers, Istanbul months, composed for unrefreshed months exactly as F3 R94 does. T1/T2/T3 and inductive/capacitive come from the same rows. A composed row sets the figure's `partial` flag (R274). |
| **R255** | **The bill is the building invoice of that period key.** "Electricity bill" = Σ `total_cost` of the **building-scope**, non-superseded bills whose `period_key` = the month (02 §10.1: "sum of the building invoices' totals"). Bill components (energy, distribution, taxes = VAT + other taxes), reactive penalty and the reactive ratios come from those bills. A bill's period follows the building's cutoff day (R233), so the info table labels it "fatura dönemi" — the report never re-slices an invoice into calendar days. |
| **R256** | **Rooftop production is the buildings' metered export; utility-scale production is the plants'.** `power_plants` has no building link (R235), so the only building-attributable generation is Σ `active_export` of the selected buildings' analyzers (legacy did the same: `activeGeneration`). Utility-scale production = Σ `plant_production_monthly.production_kwh` of the selected plants whose `plant_kind = 'grid'`. `plant_selection`: `all` → rooftop + utility-scale; `rooftop` → rooftop only; `grid` → utility-scale only. Before F9 fills `plant_production`, utility-scale is null ("veri yok"), never 0. |
| **R257** | **No default prices.** Legacy substitutes ₺2.5 purchase and ₺1.5 feed-in when it finds nothing (`MonthlyReportTab.tsx:458,462`). Purchase price per building = its bill's `effective_energy_price`; **average purchase price** = Σ `energy_cost` ÷ Σ `net_consumption` over the selected buildings' bills (per currency, omitted when the divisor is zero). Rooftop feed-in = the building bills' `generation_price_per_kwh` (one value when all agree, else a min–max range). Utility-scale feed-in = each selected plant's solar tariff effective on the period's first day, shown the same way. Anything unresolved is null. |
| **R258** | **Coverage is explicit.** A sum over buildings where some have no data carries `with_data` / `of` counts, and the screen says "3 binanın 2'si" beside it. A sum where none has data is null. |
| **R259** | **Year-over-year delta** = `(current − previous) ÷ previous × 100`, rounded half-up to 1 dp; **omitted** when either side is null or previous is zero. Monthly compares the same month of the previous year; yearly compares the previous year. |
| **R260** | **Target production (E-1).** Per plant: `yearly_target_kwh` if set and > 0; else Σ monthly targets when all twelve rows exist and the sum > 0; else null. Report target = Σ plant targets over plants **with** a target; achievement = actual ÷ target × 100 (1 dp) over the same plants only, so a plant without a target never dilutes the rate. No target anywhere → both null. |
| **R261** | **Share met by solar** = `min(production, consumption) ÷ consumption × 100` (02 §10.2); grid share = `100 − solar share`; both omitted when consumption is null or zero. Production here is the R256 total for the plant selection. |
| **R262** | **Carbon (02 §9.3–§9.4).** Factor = the `emission_factors` row keyed `grid_electricity_tr_2022`, the company's own override first (R162's lookup, reused). `consumption_t = kWh × factor ÷ 1000`, `reduction_t = production × factor ÷ 1000`, `net_t = consumption_t − reduction_t`, **not clamped** (legacy's `Math.max(0, …)` hides a net exporter). The section states the factor, its unit and `source_year`. No factor → the section is unavailable with a reason. Yearly only (§7.14 lists it there). |
| **R263** | **One report row per building (E-3).** `POST /reports/generate` takes `building_ids[]` and enqueues one `report.generate` per building; the answer lists `{building_id, report_id, job_id}` per building. `GET /reports/preview` combines the buildings in memory and persists nothing. |
| **R264** | **Report lifecycle.** Generate marks an existing row `pending` through `UpdateStatus` (its old payload and files stay readable) or upserts a new `pending` row with payload `{}`. The worker computes, renders, stores and upserts `completed`; a failure sets `error` with a scrubbed message and records a closed code on its `job_runs` row. Re-running the same building/type/period replaces (the unique key), never duplicates. |
| **R265** | **Files.** `<StorageRoot>/reports/<company_id>/<report_id>.{pdf,xlsx}`, written temp-then-rename, `0640`. A read resolves only inside `<StorageRoot>/reports/<company_id>/`. The stored files are Turkish; `GET …/pdf|excel` with `Accept-Language: en` renders from the payload on demand. A stored path that is missing re-renders from the payload — a GET never writes. A `pending` report with an empty payload answers 409 `report_not_ready`. |
| **R266** | **E-mail is a job.** `POST /reports/{id}/email` validates `to[]` (1–10 addresses, each `net/mail`-parseable, no line breaks), enqueues `report.deliver` and answers 202 `{job_id}`; the API never sends mail (F7's rule). The worker sends the report's stored `email_subject`/`email_body` (HTML) plus a plain-text alternative, attaching `rapor-<period>.pdf` and `rapor-<period>.xlsx`. A delivery failure writes a Messages row (category `report-delivery`, R222's shape: scrubbed, nothing secret) and a closed code: `smtp_not_configured`, `report_not_ready`, `delivery_failed`. Each request is a new intent: the deliver task id carries a fresh UUID. |
| **R267** | **Watchable jobs, and the F8a defect.** `report.generate` and `report.deliver` join `jobs.watchable`, visible when the payload's company matches and its building is visible to the caller. **Defect fixed here:** tasks without `asynq.Retention` are deleted on success, so `GET /jobs/{id}` answered 404 for every finished `billing.generate` and the bills screen showed "failed". When the inspector no longer holds a watchable task that records its task id, `Get` answers from the newest `job_runs` row for that id (`success` → succeeded, `failed` → failed + code, `running` → running); no row → 404 as before. |
| **R268** | **Schedules.** `report.dispatch_monthly` (`0 6 2 * *`, `EKOKOD_SCHEDULE_REPORTS_MONTHLY`) generates the **previous** Istanbul calendar month for every non-deleted building; `report.dispatch_yearly` (`0 7 3 1 *`, `EKOKOD_SCHEDULE_REPORTS_YEARLY`) the previous year. Scheduled reports use `plant_selection = all` and every company plant. Both join `ops.Triggerable`. Legacy's "current (unfinished) month on the cutoff day" is not rebuilt. |
| **R269** | **Plant ids are checked at request time.** `plant_ids[]` in preview and generate must each resolve through `PlantRepository.Get` under the caller's scope (404 otherwise); the payload carries them and the worker uses exactly those. Empty `plant_ids` means every company plant matching the selection. |
| **R270** | **Currencies never add (R253).** Money figures are lists keyed by currency; cards and the info table print one line per currency. The monthly bill chart and yearly bill chart draw the TRY series when present, else the first currency, and their footnote names any other currency omitted. |
| **R271** | **Charts (07 §5).** Monthly: consumption kWh/month and bill ₺/month, January–December of the report year vs. the previous year, grouped bars (current brand green, prior muted grey). Yearly: consumption vs. production per year and bill per year for Y−2…Y (legacy's history window), and target vs. actual per plant (grouped bar with target reference). Each chart has its data table; the PDF draws the same bars and prints the same table; the workbook carries the data sheet and a native chart. |
| **R272** | **The e-mail body** is composed at generation with `html/template` (every name escaped) in the company's outbound locale (`tr`), summarising period, buildings, total consumption, total production and bill per currency; stored in `email_subject` / `email_body`. The text alternative is rendered from the same figures at send time. |
| **R273** | **Request limits.** Preview and generate: `type` ∈ {monthly, yearly}; `period` `YYYY-MM` / `YYYY`, year in [2000, current+1]; 1–50 `building_ids`, duplicates rejected; ≤ 100 `plant_ids`; `plant_selection` ∈ {all, grid, rooftop}. Violations are 422 with field codes; unknown query parameters 400 (05 §1). |
| **R274** | **Incomplete periods are labelled.** A figure built from a composed or open month carries `partial: true`; the screen shows a `DataQualityBadge` (07 §11) and the PDF a footnote. |
| **R275** | **Archive.** `GET /reports?type&building_id&year&limit&offset` returns newest first with `total`, each item carrying building name, type, period, plant selection, status and `processed_at`. PDF/Excel are "available" when `status = completed`. Grouping (year → yearly report + monthly reports with a month count) is done by the screen over the page it holds; `limit` max 500. |

## Payload v1 (the stored snapshot and the preview answer)

`internal/domain/report` owns these types; the stored `reports.payload` is their JSON (decimals as
strings), with `"version": 1`. `dto` mirrors them field for field.

```go
type Figure struct { // a nullable quantity with its provenance
    Value   *decimal.Decimal `json:"value"`
    Partial bool             `json:"partial,omitempty"`
    WithData int             `json:"with_data"` // R258
    Of       int             `json:"of"`
}
type MoneyFigure struct {
    Currency string          `json:"currency"`
    Value    decimal.Decimal `json:"value"`
    WithData, Of int
}
type PriceRange struct{ Min, Max *decimal.Decimal } // equal when uniform; both nil when unresolved
type Delta struct{ Pct *decimal.Decimal }           // R259

type BuildingLine struct {
    BuildingID uuid.UUID; Name string
    TariffName *string; PurchasePrice *decimal.Decimal; Currency *string
}
type PlantLine struct {
    PlantID uuid.UUID; Name string; Kind string
    Production Figure; FeedIn *decimal.Decimal
    Target *decimal.Decimal; AchievementPct *decimal.Decimal
}
type MonthPoint struct{ Month int; Current, Previous *decimal.Decimal }
type YearPoint  struct{ Year int; Consumption, Production *decimal.Decimal; Bill []MoneyFigure }
type YearMonthRow struct{ Month int; Consumption, Rooftop Figure; Bill, ReactivePenalty []MoneyFigure }
type CurrencyDelta struct{ Currency string; Pct *decimal.Decimal }

type Monthly struct {
    Year, Month, DaysInMonth int
    Buildings []BuildingLine; Plants []PlantLine; Selection string
    Consumption, ConsumptionPrev, DailyConsumption Figure
    T1, T2, T3, Inductive, Capacitive Figure
    Rooftop, RooftopPrev, Utility, UtilityPrev, Production, ProductionPrev, DailyProduction Figure
    Bill, BillPrev, EnergyCost, DistributionCost, Taxes, ReactivePenalty, ReactivePenaltyPrev []MoneyFigure
    InductiveRatio, CapacitiveRatio *decimal.Decimal // weighted by active consumption (02 §10.1)
    AveragePurchasePrice []MoneyFigure                 // R257, one per currency
    RooftopFeedIn, UtilityFeedIn PriceRange
    ConsumptionDelta, ProductionDelta Delta
    BillDelta, ReactivePenaltyDelta []CurrencyDelta   // R259 per currency
    ConsumptionChart, BillChart []MonthPoint          // 12 points, R271 (bill chart in ChartCurrency)
    ChartCurrency *string; OmittedCurrencies []string // R270
}
type Yearly struct {
    Year int; Buildings []BuildingLine; Plants []PlantLine; Selection string
    Months []YearMonthRow  // 12 rows: consumption, rooftop, bill[], reactive penalty[]
    Consumption, Rooftop, Utility, Production Figure
    Bill, ReactivePenalty []MoneyFigure
    DailyConsumption, DailyRooftop, DailyProduction Figure   // ÷ days in year
    Target *decimal.Decimal; AchievementPct *decimal.Decimal // R260
    ConsumptionDelta Delta; BillDelta []CurrencyDelta
    SolarSharePct, GridSharePct *decimal.Decimal            // R261
    Carbon *Carbon                                          // nil = unavailable, CarbonReason says why
    CarbonReason string
    History []YearPoint                                     // Y-2..Y, R271
    ChartCurrency *string; OmittedCurrencies []string
}
type Carbon struct {
    Factor decimal.Decimal; FactorUnit string; SourceYear *int
    ConsumptionT, ReductionT, NetT *decimal.Decimal
}
type Payload struct {
    Version int; Type string; Period string
    Monthly *Monthly `json:"monthly,omitempty"`
    Yearly  *Yearly  `json:"yearly,omitempty"`
}
```

(Field names become snake_case JSON tags when written; the listing above omits tags for length.
Every exported field gets an explicit `json:"snake_case"` tag in the real file.)
