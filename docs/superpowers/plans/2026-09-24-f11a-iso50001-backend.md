# F11a — ISO 50001 Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this
> plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This phase runs **inline in
> one session**: no parallel agents, no subagents, no Workflow (the user's standing rule).

**Goal:** The server side of the ISO 50001 workbench (01 §7.17, 05 §13):
- the clause catalogue (5 main / 19 sub-clauses, tr + en verbatim from legacy);
- project state with progress and Gantt statuses;
- clause dates;
- notes;
- evidence files: 30 MB, type allow-list with magic-byte sniffing, stored outside any web root, served only through an authorising handler;
- generated clause templates;
- a streamed zip export.

The screens are **F11b**.

**Architecture:**
- **`internal/domain/iso50001`** is pure: the catalogue, progress and Gantt status.
- **`internal/storage`** is the file store:
  - paths are always server-generated (`<root>/iso50001/<company>/<uuid>`);
  - `Open` refuses any path outside the root;
  - `Save` streams to a temp file with a size cap, a SHA-256 and a sniff of the first 512 bytes, then renames.
- **`internal/service/iso50001`** composes F1's `ISO50001Repository` and `FileRepository` with the store and `BuildingRepository`. Building visibility is checked before every read and write.
- **ISO files** are `stored_files` rows with `owner_type='iso50001'`, **`owner_id = building_id`**, and `clause_id`. So a file's building is checked with `Buildings.Get(scope, owner_id)`, with no new store query.
- **Templates** are generated on request: excelize workbooks and one fpdf instruction.
- **The export** writes `archive/zip` straight to the response: notes as `notes/<clause>.md`, files as `files/<clause>/<name>`.

**Tech Stack:** Go 1.27, pgx/sqlc, excelize, go-pdf/fpdf, archive/zip.

## Rulings (R330–R341)

| Id | Rule |
|---|---|
| **R330** | **Catalogue.** The main clauses are 5–9. The subs are 5.1–5.3, 6.1–6.6, 7.1–7.5, 8.1–8.3 and 9.1–9.3 (19). Each has a title and a description in tr and en, verbatim from legacy. Templates: 6.3 → `significant-energy-uses`; 6.4, 6.5, 9.1 → `energy-consumption-analysis`; 7.5 → `regression-analysis-instruction`. |
| **R331** | **Project.** Created on the first write (`EnsureProject`). A read without a project answers the empty state: no dates, zero counts, progress 0. |
| **R332** | **Dates.** `PUT /iso50001/{building_id}/dates {clauses:[{clause_id,start,end}]}`. All five main clauses are required, each with both dates and `start ≤ end`. Errors:<br>• `clauses: incomplete`;<br>• `clauses.<id>: start_after_end`;<br>• an unknown or duplicate id → `clauses: invalid`. |
| **R333** | **Progress (Q-G5).** As in the table above. |
| **R334** | **Gantt (Q-G4).** Per main clause, with Istanbul `today`:<br>• no dates → no status;<br>• all its subs done → `completed`;<br>• `today > end` → `expired`;<br>• `today < start` → `not_started`;<br>• otherwise `in_progress` if any sub is done, else `not_started`.<br>`gantt_available` is false unless all five have dates; the screen then shows legacy's message. `project_start`/`project_end` are the min start and max end. |
| **R335** | **Notes.** `POST /{building_id}/clauses/{clause}/notes {title?, body}`: the clause must be one of the 19; title ≤ 200; body 1–10 000 (trimmed). `PATCH /notes/{id} {title?, body}` and `DELETE /notes/{id}` go through the scoped SQL. Notes are listed per clause, newest first. |
| **R336** | **Upload.** `POST /{building_id}/clauses/{clause}/files`, multipart field `file`:<br>• the size cap is `cfg.Storage.UploadMax` (30 MB) → 413 `file: too_large` with the limit;<br>• the name is trimmed to its base name, ≤ 200 characters, no control characters.<br>**Sniffing:**<br>• `%PDF-` → pdf;<br>• `PK\x03\x04` + `.xlsx`/`.docx` → OOXML;<br>• `D0 CF 11 E0` + `.xls` → ms-excel;<br>• `\x89PNG` → png; `FF D8 FF` → jpeg;<br>• valid UTF-8 text + `.csv` → csv;<br>• anything else, or a sniff that disagrees with the extension → 422 `file: type_not_allowed`.<br>The type must also be in `cfg.Storage.AllowedTypes`. |
| **R337** | **Storage.** `<root>/iso50001/<company_id>/<uuid>` with no user input in the path. `Open(company, stored_path)` cleans the path and requires it under `<root>/iso50001/<company_id>/`, else `ErrOutsideRoot` (tested with `../`, absolute paths and symlinks). |
| **R338** | **Download and delete.** `GET /iso50001/files/{id}`:<br>• the file must be `owner_type='iso50001'`, not deleted, and in the company, with its building visible; else 404;<br>• headers: `Content-Disposition: attachment` with the RFC 5987 name, `X-Content-Type-Options: nosniff`, the stored type.<br>`DELETE /files/{id}` soft-deletes and keeps the bytes (repository contract). |
| **R339** | **Export.** `GET /{building_id}/export` streams `application/zip`:<br>• `README.txt` (building, generated at, the TS EN ISO 50001:2018 guidance note);<br>• `notes/<clause>.md`, one per clause with notes: the title, then each note's title, date and body;<br>• `files/<clause>/<original_name>`, with duplicate names suffixed ` (2)`.<br>`zip.NewWriter(w)` writes straight to the response, and bytes are copied from disk with `io.Copy`. |
| **R340** | **Templates.** `GET /iso50001/templates` → `[{id, file_name, clauses, description_tr, description_en}]`. `GET /iso50001/templates/{id}` streams the generated file, deterministic for a fixed clock. |
| **R341** | **Permissions.** `iso50001.read` = all roles (scope); `iso50001.edit` = A CA BA (05 §13). A BA writes only in their buildings; a demo user reads. |

## Review Focus

1. **Path traversal through a stored path or a crafted file name.** The name never reaches the path; `Open` rejects anything outside the company directory (Task 2).
2. **A renamed executable (`.pdf` holding `MZ`) or a PDF renamed `.xlsx`.** Rejected (Task 2).
3. **A BA with a file or note id of another building.** 404 on download, delete, update and export (Task 5).
4. **A 31 MB upload.** 413 with the limit named; no partial file is left on disk (Task 2 + 5).
5. **An export with two files named alike in one clause.** Both entries are present (Task 4).
